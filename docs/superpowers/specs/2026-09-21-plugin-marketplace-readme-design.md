# 大学生多文体写作插件发布设计

日期：2026-09-21

## 目标

把现有 `university-student-writing` Skill 整理为可提交到 ChatGPT 与 Codex 统一插件目录的“仅技能”插件，同时提供一份适合 GitHub 首页和潜在用户阅读的高质量 README。

交付物应同时满足三种场景：

1. 普通大学生能够快速判断插件能否解决自己的写作问题；
2. Codex 用户能够按照说明安装、调用和验证；
3. 发布者能够把打包结果上传到 OpenAI 插件提交门户。

## 受众与定位

主要受众是需要完成课程论文、社会实践、学生工作、校园新闻、申请和求职材料的中国大学生。次要受众是希望检查、扩展或二次发布 Skill 的开发者与教育工作者。

核心定位：不是替学生编造内容的“万能写作器”，而是一个依据真实规范选择文体、搭建结构、生成可编辑 LaTeX 项目并执行可观察校验的写作基础设施。

## 仓库结构

仓库转换为可移植的仅技能插件根目录：

```text
university-student-writing/
├── plugin.json
├── README.md
├── LICENSE
├── .gitignore
├── docs/
│   └── superpowers/specs/
├── skills/
│   └── university-student-writing/
│       ├── SKILL.md
│       ├── agents/openai.yaml
│       ├── assets/
│       ├── references/
│       ├── scripts/
│       ├── tests/
│       └── sources.md
└── scripts/
    └── package_plugin.py
```

`plugin.json` 使用 Agent Plugins 可移植清单。插件只包含 Skill，不包含 MCP 服务器、外部账号连接、网络服务或生命周期钩子。Skill 的运行能力和现有边界保持不变。

打包脚本生成干净的上传压缩包，排除 `.git`、测试缓存、编译产物和本地临时文件；源码仓库本身仍保留测试与研究来源。

## README 信息架构

README 采用中文为主、英文摘要为辅的结构：

1. 一句话价值主张：从“我该怎么写”到可编译、可检查的规范 LaTeX 项目；
2. 明确展示 6 类场景、70 种文体、中文与英文模板；
3. 用短示例展示自然语言调用、显式 `$university-student-writing` 调用和命令行生成；
4. 解释学校模板优先、真实事实优先和可见待填写字段；
5. 给出本地 Skill、GitHub 仓库和插件目录三种安装或使用方式；
6. 提供目录结构、测试状态、适用边界、贡献方式和许可证；
7. 列出几个高意图使用案例，而不是展示全部 70 个文体的冗长清单；完整列表通过生成器的 `--list` 获取；
8. 不使用未经证明的“官方”“唯一”“完全符合”等宣传语。

README 的视觉风格保持克制：少量徽章、清晰分区、短段落、代码块和一张能力矩阵。暂不依赖外部图片服务，避免链接失效；商店 Logo 和截图作为提交材料单独准备。

## 插件清单

`plugin.json` 至少包含：

- Agent Plugins 1.0.0 schema；
- 稳定的插件标识 `university-student-writing`；
- 语义版本 `1.0.0`；
- 简明英文描述；
- MIT 许可证；
- 与大学生写作、LaTeX、教育、学术写作有关的关键词；
- `extensions.com.openai.interface` 下的展示名称、短描述、长描述、分类、能力、品牌色和默认提示词。

发布者姓名、仓库 URL、网站、支持、隐私政策和条款 URL 不凭空填写。它们由发布者在获得公开地址后加入清单或提交门户。插件不采集、不上传、不持久化用户数据；README 会明确说明本地处理边界。

## 验证

实施完成后必须：

- 验证 `plugin.json` 是有效 JSON，并满足可移植插件的必需字段；
- 验证 Skill 位于 `skills/university-student-writing/SKILL.md`；
- 重新运行 Skill 结构校验；
- 运行全部单元测试与代表性 XeLaTeX 编译测试；
- 运行打包脚本并检查压缩包目录结构；
- 扫描 README、清单和包内文件，不得含未完成占位标记、示例域名、绝对本机路径或编译缓存；
- 保持 Git 工作树干净并记录最终提交号。

## 发布流程与人工环节

完成的压缩包可在 OpenAI 插件提交门户中以“仅技能”类型创建草稿。发布者仍需亲自完成身份验证、选择公开开发者身份、填写实际网站和政策 URL、上传合法 Logo 与截图、确认国家范围和合规声明，并提交审核。OpenAI 审核通过后，由发布者在门户中执行最终发布。

GitHub 建议作为源码、问题反馈、发布说明和支持页面；它不能替代 OpenAI 插件目录的提交与审核。
